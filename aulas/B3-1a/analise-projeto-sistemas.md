# B3 · 1ª SÉRIE · ANÁLISE E PROJETO DE SISTEMAS — Plano de aulas ITA NEGRO

- Componente I.14 (plano 612) · Função: Análise e projeto de sistemas de informação ·
  Classificação: Planejamento
- Carga: 80 h-a no bimestre (5 aulas/semana × 16 semanas)
- Competências/habilidades do plano: 1.1 coletar requisitos de usuários e sistemas ·
  1.2 métodos de abordagem, coleta de dados e procedimentos de pesquisa · 2.1 aplicar modelo
  Cascata · 2.2 aplicar modelos Ágeis a projetos de software
- Bases tecnológicas: conceitos de análise e projeto, ciclo de vida (viabilidade,
  especificação de requisitos, Cascata, Ágeis), introdução à análise e projeto orientado a objetos
- Valores: criatividade, organização, resolução de situações-problema
- Papel no ITA NEGRO: ESPECIFICAR O PRODUTO DA CASA — a turma descobre com "clientes" reais
  (comunidade escolar) o que o sistema precisa fazer, escolhe o método de trabalho e congela
  o escopo da versão 1.0. Este documento alimenta Banco de Dados I (B4) e o TCC (3ª série).
- Formato aula-âmbar: 15 teoria + 30 prática + 5 retrospectiva.

## Sequência didática

| Sem | Base tecnológica (plano) | Prática guiada (30 min) | Evidência |
|-----|--------------------------|--------------------------|-----------|
| 1 | Diagnóstica + conceitos de análise de sistemas | Estudo de caso: por que sistemas fracassam | Ficha diagnóstica |
| 2 | Ciclo de vida: estudo de viabilidade | Viabilidade do produto (técnica, operacional, econômica) em equipe | Matriz de viabilidade |
| 3 | Ciclo de vida: escopo inicial | Declaração de problema + visão do produto (1 página) | Documento de visão v1 |
| 4 | Métodos de coleta: entrevista | Roteiro de entrevista; treino em dupla (entrevistador/entrevistado) | Roteiro validado |
| 5 | Métodos de coleta: questionário | Questionário para a comunidade escolar (formulário online) | Questionário no ar |
| 6 | Métodos de coleta: observação | Observação in loco do problema (visita/gincana de campo) | Caderno de campo |
| 7 | Análise dos dados coletados | Tabular respostas; priorizar dores (matriz impacto×esforço) | Dados tabulados |
| 8 | Especificação de requisitos | Requisitos funcionais e não funcionais do produto | Checkpoint 1: RF/RNF v1 |
| 9 | User stories e critérios de aceite | Escrever histórias no formato "como X, quero Y, para Z" | Backlog v1 |
| 10 | Modelo Cascata | Simular fases em cascata para 1 requisito (documento em sequência) | Checkpoint 2: exercício cascata |
| 11 | Modelos Ágeis: Scrum | Papéis, sprint, cerimônias — kanban da casa no quadro/taiga | Kanban da equipe |
| 12 | Modelos Ágeis: primeira sprint | Sprint de 1 semana: 3 histórias "prontas" (definição de feito) | Burndown simples |
| 13 | Intro análise orientada a objetos | Identificar objetos/classes do produto (substantivos→classes) | Lista de classes v0 |
| 14 | Escolha do modelo + revisão | Cada equipe defende: cascata ou ágil para a casa? (debate) | Justificativa metodológica |
| 15 | MARCO B3: especificação congelada | Banca: requisitos + backlog + método escolhido, com "cliente" convidado | Documento de requisitos v1.0 |
| 16 | Defesa + autoavaliação | Portfólio: o que muda se o cliente mudar de ideia? | Portfólio + menção |

## Avaliação (formato plano 612)
- Diagnóstica: sem. 1 · Formativa: retrospectivas + validação contínua com o "cliente".
- Cumulativa: checkpoints (sem. 8 e 10) + marco (sem. 15, requisitos congelados).
- Autoavaliação: portfólio. Recuperação contínua: sem. 14 — refação da especificação com
  tutoria antes do fechamento.
